LLM AGENT · RAG + RERANK · SHEETS API · GTM

COLDSTART

Cold email, minus the cold sweat.

The problem: sales was researching every prospect by hand — dig for news, guess which of 3,000+ reports fits, write four emails, repeat. It ate the better part of an hour per lead, and quality fell off a cliff after lunch. What I shipped: an agent that takes a sheet of company names and returns a finished four-touch cadence. It screens for a real trigger event — funding, expansion, a merger, fresh regulation — so every email opens with something that actually happened this quarter, then retrieves and reranks the report catalog to attach the one asset that earns a reply. The call I made: the sheet stays the interface. I could have built a clean dashboard nobody logs into; instead the output lands in the tool the team already lives in, so adoption cost was zero and training was one Slack message. Boring choice, correct choice. Sales now wakes up to a finished cadence and takes the credit. I have made my peace with that.

RETRIEVAL DESIGN · COST/ACCURACY TRADEOFF · DATA QUALITY

BESTFIT

3,000 reports. One defensible answer per lead.

The problem: purchased B2B lists rot in two directions at once — the report matched to the lead is usually wrong, and the lead usually does not work there anymore. The architecture decision: two-stage retrieval. Embeddings do the cheap, fast shortlist across the full catalog; the LLM reranks only the survivors. Single-stage LLM matching would have been marginally more accurate and roughly an order of magnitude more expensive per lead — at our volume that is the difference between a tool that ships and a line item someone kills in Q3. The failure mode nobody specced: stale employment. An email about someone's old employer's industry is worse than no email, so the tool confirms the lead is still there before it trusts the match, and silently rematches under the new company when they are not. How I knew it worked: a fixed set of hard, hand-labelled leads I rerun before every change, so "the new prompt feels better" never made it to production on vibes alone. Every row that comes out has a reason to exist that survives a pipeline review.

WEIGHTED SCORING · SEARCH CONSOLE API · BULK MODE

RANK X-RAY

Turns "why are we losing?" into a ranked to-do list.

The problem: "why does that page outrank ours" was being answered with instinct and the phrase "content is king", which is not a roadmap. What I shipped: point it at a URL and it does the two-hour consultant audit in about a minute — finds the page each rival ranks with for the same intent, tears both down side by side, and scores the gap across content depth, schema coverage, internal link structure, E-E-A-T signals, and whether AI overviews are citing them instead of you. The call I made: every factor carries an explicit weight. That is the whole product. A weight can be argued with in a meeting and tuned when it is wrong; a gut feeling can only be agreed with or ignored. So the output is not a diagnosis, it is a prioritized backlog — biggest scoring gap first, smallest effort as the tiebreak. Bulk mode runs the same X-ray across a CSV of URLs and enriches every row with live rank, CTR, impressions and clicks from the Search Console API: one upload in, a full portfolio triage out.

OPENAI API · HUMAN-IN-THE-LOOP · SERVERLESS · VERCEL

LINKLOOM

Internal links that place themselves. Politely.

The problem: internal linking is the task everyone agrees matters and nobody does — it means rereading the entire library, remembering what exists, and finding anchor text that does not read like a robot wrote it. Every single time you publish. What I shipped: a tool that reads the content library, works out what each piece is genuinely about, and proposes contextual placements — real anchor text inside real sentences, pointing at the actually-related piece. The call I made: it suggests, it never publishes. Auto-inserting links into live pages is a fast way to teach an editorial team to distrust your tool forever, and trust is the only feature that matters twice. A human approves in seconds; the tool keeps its job. The unglamorous part: strict frontend/backend split, serverless on Vercel, API key server-side in environment config — because "we leaked the key" is a rough way to open a standup. Running against a production content library, not a demo dataset.
